● Document Processing Infrastructure

A distributed engine for enterprise document processing.

PDF Suite is an end-to-end distributed SaaS monorepo. It features instant client-side WebAssembly for small files, a high-throughput Fastify REST gateway, asynchronous BullMQ/Redis worker pipelines, and a native Flutter mobile application with complete feature parity.

02 • System Architecture

Three Architectural Foundations

01 • Hybrid Strategy

WASM + Cloud Workers

Files under 15MB are processed directly in the client browser using WebAssembly. Heavier multi-document operations seamlessly dispatch to background cloud workers.

Zero Server Cost on 70%+ of Jobs
02 • Asynchronous Pipeline

BullMQ & Dead-Letter Queues

Jobs are produced into Redis queues with exponential backoff retries, dead-letter quarantine, and an automated 24-hour TTL purge daemon for zero persistent data retention.

Fault-Tolerant Job Bus
03 • Monorepo Boundaries

Turborepo Orchestration

Unified workspace boundaries with shared canonical TypeScript contracts (@pdf-suite/shared-types), shared core logic, and parallelized Docker container builds.

Optimized Caching & Type Safety
03 • Specialized Runtimes

Headless Microservice Engines

Each conversion task is delegated to the optimal runtime environment.

QPDF Processor
Split & Merge Engine

Lossless page-level stream parsing producing linearized, fast-web PDF output.

Sharp Engine
JPG to PDF Pipeline

High-speed libvips native compilation preserving input image dimensions and DPI.

Python Worker
PDF to Word Conversion

Headless LibreOffice service converting documents to reflowable DOCX files.

TTL Cleaner
Automated Purge Daemon

Scheduled cron purging expired blobs from S3/MinIO after 24 hours.

04 • Getting Started

Run Locally in Under 3 Minutes

# 1. Clone repository and install dependencies
$ git clone https://github.com/Subhash6102003/pdf-suite-monorepo.git && cd pdf-suite-monorepo && pnpm install
# 2. Start PostgreSQL, Redis & MinIO services via Docker Compose
$ docker compose -f services/workers/docker/docker-compose.dev.yml up -d
# 3. Push database schema and start development cluster
$ pnpm --filter infra db:push && pnpm dev
